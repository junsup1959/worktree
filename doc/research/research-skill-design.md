# Research Skill 인사이트와 유형

> 상태: 단순한 Research Skill을 위한 설계 메모
> 범위: 한 에이전트가 필요한 자료를 찾고, 내용을 확인하고, 출처와 함께 답하는 능력

## 1. Research Skill이란

Research Skill은 사용자의 질문에 답하는 데 필요한 정보를 웹, 문서, 논문,
코드, 데이터 같은 정보원에서 찾아 확인하고, 핵심만 정리해 근거와 함께
전달하는 Skill이다.

핵심 흐름은 단순하다.

```text
질문 이해
  -> 자료 찾기
  -> 원문 읽기
  -> 중요한 내용 확인
  -> 답변 정리
  -> 출처 표시
```

검색이 자료를 발견하는 행위라면, 리서치는 발견한 자료가 실제로 질문에
답하는지 확인하고 여러 자료의 내용을 하나의 답으로 정리하는 행위다.

### 이 문서에서 다루는 것

- 공개 웹, 공식 문서, 논문, 제공 파일, 코드베이스, 구조화 데이터 조사
- 출처의 신뢰도와 최신성 확인
- 중요한 사실의 교차 확인
- 조사 결과의 요약, 비교, 종합
- 주장과 가까운 위치에 출처 표시

### 이 문서에서 다루지 않는 것

- 여러 에이전트의 역할 분담과 작업 조율
- 장시간 자율 실행이나 예약 작업
- 별도의 실행 하네스와 평가 시스템
- Research Skill로 다른 Skill을 만드는 과정

## 2. 좋은 Research Skill의 조건

### 2.1 질문을 먼저 분명하게 만든다

사용자가 실제로 알고 싶은 것, 조사 범위, 기준 시점, 원하는 결과 형태를
파악한다. 질문이 충분히 명확하면 불필요한 확인 절차 없이 바로 조사한다.

예를 들어 “A가 좋은가?”라는 질문은 다음에 따라 답이 달라질 수 있다.

- 누구에게 좋은가?
- 어떤 용도인가?
- 무엇과 비교하는가?
- 현재 정보가 필요한가, 일반적인 설명이 필요한가?

### 2.2 검색 결과가 아니라 원문을 읽는다

검색 결과의 제목과 요약문은 자료를 찾는 단서일 뿐이다. 실제 답변의 근거로
사용할 때는 원문을 열어 문맥, 날짜, 조건, 예외를 확인해야 한다.

### 2.3 질문에 맞는 출처를 고른다

출처는 많을수록 좋은 것이 아니라 질문에 적합할수록 좋다.

일반적인 우선순위는 다음과 같다.

1. 공식 문서, 원문 발표, 법령, 표준, 원 데이터
2. 원 논문, 기술 보고서, 기관 보고서
3. 신뢰할 수 있는 전문 매체와 독립 분석
4. 블로그, 포럼, 소셜 게시물

사용자 경험이나 현장 반응을 조사할 때는 포럼과 소셜 게시물이 유용할 수
있지만, 공식 사실을 확인하는 출처와 같은 방식으로 취급하지 않는다.

### 2.4 중요한 사실은 교차 확인한다

가격, 날짜, 수치, 지원 여부, 정책처럼 결론을 바꿀 수 있는 사실은 가능하면
서로 독립적인 자료나 더 직접적인 원출처로 한 번 더 확인한다.

여러 문서가 같은 보도자료를 인용했다면 독립된 여러 근거로 세지 않는다.

### 2.5 최신성이 필요한 질문은 날짜를 확인한다

현재 상태, 최근 변경, 가격, 정책, 제품 사양을 묻는 질문은 오래된 자료가
정확했던 적이 있다는 사실만으로 충분하지 않다. 게시일뿐 아니라 실제 변경이
일어난 날짜도 구분한다.

### 2.6 사실과 해석을 구분한다

답변에는 다음 세 가지가 섞일 수 있다.

- 출처에서 직접 확인한 사실
- 여러 사실을 바탕으로 한 해석이나 추천
- 자료만으로 확정할 수 없는 부분

좋은 Research Skill은 이 경계를 숨기지 않는다. 추론한 내용은 추론이라고
밝히고, 확인할 수 없는 내용은 단정하지 않는다.

### 2.7 답을 먼저 쓰고 근거를 붙인다

조사 과정을 길게 나열하기보다 사용자의 질문에 대한 결론부터 전달한다.
그 뒤에 핵심 근거, 차이점, 한계, 출처를 필요한 만큼 붙인다.

### 2.8 출처 링크만 나열하지 않는다

좋은 결과물은 링크 모음이 아니다. 각 출처에서 무엇을 확인했고 그것이 답변의
어떤 부분을 뒷받침하는지 알 수 있어야 한다.

## 3. 기본 조사 절차

### 1단계: 질문과 범위를 잡는다

- 무엇을 답해야 하는가?
- 어느 시점의 정보가 필요한가?
- 비교나 추천이 필요한가?
- 사용자가 원하는 답변 길이와 형태는 무엇인가?

### 2단계: 적절한 자료를 찾는다

핵심 검색어와 동의어를 사용해 후보 자료를 찾는다. 공식 정보가 있는 주제는
공식 출처부터 확인하고, 관점이나 경험이 필요한 경우에만 보조 출처를 넓힌다.

### 3단계: 원문에서 근거를 확인한다

제목이나 검색 요약만 보지 않고 실제 문서를 읽는다. 답변에 사용할 문장이
원문의 취지와 맞는지, 조건이나 예외가 빠지지 않았는지 확인한다.

### 4단계: 핵심 내용을 정리한다

질문에 직접 필요한 사실만 남긴다. 자료 사이에 차이가 있으면 어느 쪽을
선택적으로 숨기지 말고 차이와 가능한 이유를 함께 적는다.

### 5단계: 출처와 함께 답한다

결론을 먼저 쓰고, 근거가 필요한 주장 가까이에 출처를 붙인다. 마지막에는
불확실성이나 조사 범위의 한계가 있을 때만 간단히 밝힌다.

## 4. Research Skill을 분류하는 세 축

Research Skill의 종류를 한 가지 기준으로만 나누면 서로 다른 개념이 섞인다.
다음 세 축을 따로 분류해야 한다.

| 축 | 답하는 질문 | 예시 |
| --- | --- | --- |
| 조사 목적 | 왜 조사하는가? | 사실 확인, 개요, 비교, 최신 동향, 근거 종합 |
| 조사 대상·정보원 | 무엇을 어디에서 조사하는가? | 공개 웹, 공식 문서, 논문, 파일, 코드, 데이터 |
| 조사 방법 | 어떻게 찾고 확인하는가? | 웹 검색, 원문 열람, 코드 검색, 데이터 조회, 교차 확인 |

예를 들어 “최근 Python 버전의 주요 변경점을 조사해 달라”는 요청은 다음처럼
분해할 수 있다.

```text
목적: 최신 동향 + 주제 개요
대상: Python 공식 문서와 공개 웹
방법: 날짜를 제한한 웹 검색 + 공식 릴리스 노트 원문 확인
```

“웹 서칭”은 엄밀히 말하면 조사 대상이 아니라 자료를 찾는 방법이다. 그러나
실제 Skill 이름에서는 `공개 웹`이라는 대상과 `웹 검색·브라우징`이라는 방법을
묶어 Web Research라고 부르는 것이 자연스럽다.

## 5. 조사 목적에 따른 유형

다음 항목은 하나의 Research Skill이 질문의 모양에 따라 선택하는 목적 모드다.

| 유형 | 적합한 질문 | 핵심 확인 내용 | 결과 형태 |
| --- | --- | --- | --- |
| 사실 확인 | “현재 가격은?”, “지원하는가?” | 가장 직접적이고 최신인 출처 확인 | 짧은 답, 근거, 출처 |
| 주제 개요 | “이 분야가 무엇인가?” | 핵심 개념, 구성, 주요 쟁점 파악 | 구조화된 개요 |
| 비교 조사 | “A와 B 중 무엇이 다른가?” | 같은 기준으로 각 대안 확인 | 비교표 또는 항목별 비교 |
| 최신 동향 | “최근 무엇이 바뀌었나?” | 날짜와 변경 전후 상태 확인 | 현재 상태와 변화 요약 |
| 근거 종합 | “여러 자료는 무엇을 말하나?” | 여러 근거의 공통점과 차이 확인 | 합의점, 차이, 한계 |

### 5.1 사실 확인

하나의 구체적인 사실을 빠르고 정확하게 확인하는 유형이다. 최신 정보가
중요하면 날짜를 확인하고, 공식 출처가 있으면 이를 우선한다.

```text
답: 확인된 사실
근거: 필요한 조건이나 예외
출처: 직접 근거가 되는 자료
```

### 5.2 주제 개요

낯선 주제를 이해할 수 있도록 큰 그림을 제공하는 유형이다. 모든 세부 정보를
모으기보다 핵심 개념, 주요 구성 요소, 현재 쟁점을 먼저 정리한다.

좋은 개요는 독자가 다음에 무엇을 더 조사해야 할지도 알 수 있게 한다.

### 5.3 비교 조사

제품, 기술, 정책, 방법론 같은 대안을 같은 기준으로 비교하는 유형이다.
대안별 설명을 따로 모으는 데서 끝내지 않고 동일한 기준을 적용해야 한다.

비교 기준의 예시는 다음과 같다.

- 기능과 제약
- 비용
- 사용 난이도
- 호환성
- 유지보수성
- 적합한 사용 사례

추천까지 요청받았다면 사용자의 조건에 비추어 어떤 대안이 더 적합한지
설명한다. 보편적인 승자를 만들 필요는 없다.

### 5.4 최신 동향

최근 발표, 정책 변경, 제품 업데이트, 시장 변화를 확인하는 유형이다.
게시된 날짜와 사건이 발생한 날짜를 구분하고, 과거 상태와 현재 상태를 섞지
않는다.

결과에는 다음이 포함되면 충분하다.

- 무엇이 바뀌었는가?
- 언제 바뀌었는가?
- 이전과 무엇이 다른가?
- 사용자에게 어떤 영향이 있는가?

### 5.5 근거 종합

여러 출처를 읽고 공통된 결론과 차이를 정리하는 유형이다. 대상은 논문일 수도,
웹 자료나 사용자가 제공한 문서일 수도 있다.

자료의 내용을 단순히 하나씩 요약하기보다 다음을 구분한다.

- 여러 자료가 공통으로 말하는 것
- 서로 다른 결론이나 전제를 가진 부분
- 아직 자료가 부족한 부분
- 자료의 범위 때문에 일반화하기 어려운 부분

### 조사 깊이는 별도 목적이 아니다

Quick Research와 Deep Research의 차이는 질문의 종류가 아니라 조사 범위와
근거의 양이다. 사실 확인, 비교, 최신 동향, 근거 종합 모두 필요에 따라 짧게
조사하거나 깊게 조사할 수 있다.

## 6. 조사 대상·정보원에 따른 유형

조사 대상은 필요한 도구, 자료를 찾는 방식, 신뢰도 판단 기준을 바꾼다.
따라서 별도의 Research Skill을 나눌 때는 목적보다 대상이 더 강한 분리 기준이
될 수 있다.

| 대상 유형 | 대표적인 정보원 | 주된 접근 방법 | 특히 확인할 것 |
| --- | --- | --- | --- |
| 공개 웹 | 웹페이지, 뉴스, 블로그 | 검색어·도메인·날짜 검색 후 원문 열람 | 최신성, 원출처, 검색 요약의 왜곡 |
| 공식·1차 자료 | 제품 문서, 법령, 표준, 공지, 원 데이터 | 공식 사이트 탐색과 직접 조회 | 버전, 시행일, 적용 범위 |
| 학술 문헌 | 논문, 학회 자료, 연구 보고서 | 학술 검색과 인용 문헌 추적 | 연구 설계, 표본, 출판 상태, 한계 |
| 제공 문서·파일 | PDF, 문서, 프레젠테이션, 이미지 | 파일 열람, 문서 내 검색, 위치별 인용 | 누락된 페이지, 표·각주, 문서 범위 |
| 코드베이스 | 소스 코드, 설정, 테스트, 변경 이력 | 파일·심볼·참조 검색과 실행 경로 추적 | 실제 동작과 문서의 차이, 현재 버전 |
| 구조화 데이터 | CSV, 스프레드시트, 데이터베이스, API | 필터링, 질의, 집계, 계산 | 스키마, 단위, 기간, 결측치 |
| 커뮤니티 자료 | 포럼, 리뷰, 소셜 게시물 | 여러 사례 검색과 공통 패턴 비교 | 표본 편향, 광고, 사실과 경험의 구분 |
| 내부 업무 자료 | 위키, 드라이브, 이슈, 업무 기록 | 권한이 허용된 범위의 검색과 문서 열람 | 접근 권한, 민감 정보, 기준 시점 |

이 대상들은 서로 배타적이지 않다. 공식 API 문서는 공개 웹이면서 공식 자료이고,
사용자가 첨부한 논문 PDF는 제공 문서이면서 학술 문헌이다. 실제 조사에서는
필요한 대상 유형을 함께 선택한다.

### 6.1 Web Research

공개 웹을 대상으로 검색 엔진과 브라우징을 사용한다. 폭넓은 주제 탐색과 최신
정보 확인에 적합하지만, 검색 결과의 순위나 요약을 곧바로 근거로 사용해서는
안 된다.

### 6.2 Official Source Research

공식 문서와 1차 자료를 대상으로 한다. 제품 사양, 정책, 법령, 표준처럼
정확한 표현과 적용 조건이 중요한 질문에 적합하다. 문서의 버전과 효력 발생
시점을 함께 확인한다.

### 6.3 Literature Research

논문과 연구 보고서를 대상으로 한다. 개별 논문의 결론만 옮기기보다 연구의
조건, 한계, 다른 연구와의 일치 여부를 함께 본다.

### 6.4 Document Research

사용자가 제공한 문서나 지정된 파일 집합을 대상으로 한다. 문서 밖의 지식을
섞어도 되는지 먼저 구분하고, 답변이 어느 페이지나 구절에서 나온 것인지
찾을 수 있게 한다.

### 6.5 Codebase Research

코드, 설정, 테스트를 대상으로 현재 구현과 구조를 조사한다. README의 설명만
따르지 않고 실제 호출 관계와 실행 경로를 확인한다.

### 6.6 Data Research

표, 데이터베이스, API 응답처럼 구조화된 데이터를 대상으로 한다. 숫자를
계산하기 전에 열의 의미, 단위, 기간, 분모를 먼저 확인한다.

### 6.7 Community Research

사용 후기와 현장 경험을 파악하기 위해 커뮤니티 자료를 조사한다. 경험을
공식 사실의 대체물로 쓰지 않고, 반복해서 나타나는 패턴과 예외를 구분한다.

### 6.8 Internal Knowledge Research

조직 내부 문서와 업무 기록을 대상으로 한다. 공개 웹보다 현재 업무 맥락에
가까울 수 있지만, 접근 권한과 민감 정보의 경계를 지켜야 한다.

## 7. 조사 방법에 따른 유형

하나의 조사에서 여러 방법을 순서대로 사용할 수 있다. 방법은 조사 대상에서
근거를 얻기 위한 구체적인 동작이다.

| 방법 | 하는 일 | 주로 쓰이는 대상 |
| --- | --- | --- |
| 검색 | 검색어, 도메인, 날짜 조건으로 후보 자료 발견 | 공개 웹, 공식 사이트, 학술 문헌 |
| 탐색·브라우징 | 링크와 문서 구조를 따라 관련 원문 확인 | 웹사이트, 공식 문서, 위키 |
| 전문 검색 | 긴 문서에서 키워드, 표, 페이지, 구절 찾기 | PDF, 제공 문서, 보고서 |
| 코드 검색·추적 | 파일, 심볼, 참조, 호출 관계, 테스트 확인 | 코드베이스 |
| 질의·계산 | 조건에 맞는 데이터를 조회하고 집계·계산 | 데이터베이스, API, 표 |
| 교차 확인 | 같은 사실을 원출처나 독립 자료와 대조 | 모든 대상 |
| 비교 | 공통 기준으로 여러 대상의 차이 정리 | 제품, 기술, 정책, 자료 집합 |
| 종합 | 여러 근거의 공통점, 차이, 한계를 하나의 답으로 정리 | 문헌, 문서, 다중 출처 조사 |

### 방법 선택의 기본 원칙

- 자료가 어디 있는지 모르면 검색부터 한다.
- 공식 위치를 알고 있으면 검색을 거치지 않고 직접 조회한다.
- 검색으로 자료를 찾은 뒤에는 반드시 원문 열람으로 넘어간다.
- 코드와 데이터는 일반 웹 설명보다 실제 저장소와 데이터 자체를 우선한다.
- 결론을 바꿀 수 있는 사실은 교차 확인한다.
- 여러 대안을 다룰 때는 같은 기준으로 비교한다.

## 8. 목적·대상·방법 조합 가이드

### 8.1 조사 목적을 고른다

```text
구체적인 한 가지 사실을 묻는가?
  -> 사실 확인

주제의 큰 그림을 알고 싶은가?
  -> 주제 개요

둘 이상의 대안을 고르거나 차이를 알고 싶은가?
  -> 비교 조사

최근 변경과 현재 상태가 핵심인가?
  -> 최신 동향

여러 자료의 의미를 합쳐야 하는가?
  -> 근거 종합
```

### 8.2 대상과 방법을 붙인다

질문의 목적을 정한 뒤, 답이 존재하는 정보원과 그 정보원에 맞는 방법을
선택한다.

| 요청 예시 | 목적 | 대상·정보원 | 주요 방법 |
| --- | --- | --- | --- |
| “현재 이 제품의 가격은?” | 사실 확인 | 공식 사이트 | 직접 조회, 날짜 확인 |
| “최근 정책이 어떻게 바뀌었나?” | 최신 동향 | 공식 공지와 공개 웹 | 날짜 검색, 변경 전후 비교 |
| “A와 B의 실제 사용 경험을 비교해 달라” | 비교 조사 | 공식 문서와 커뮤니티 | 기준별 비교, 여러 후기 교차 확인 |
| “이 논문들은 무엇에 합의하는가?” | 근거 종합 | 학술 문헌 | 학술 검색, 원문 읽기, 종합 |
| “이 저장소의 인증 흐름은?” | 주제 개요 | 코드베이스 | 심볼 검색, 호출 관계와 테스트 추적 |
| “이 CSV에서 월별 변화는?” | 최신 동향 | 구조화 데이터 | 스키마 확인, 집계, 계산 |
| “첨부한 계약서의 해지 조건은?” | 사실 확인 | 제공 문서 | 전문 검색, 조항과 페이지 확인 |

한 요청에는 여러 목적과 대상이 함께 들어갈 수 있다. 중요한 것은 이들을
하나의 “리서치 유형”으로 뭉뚱그리지 않고 필요한 조합을 명시하는 것이다.

## 9. 결과물 형식

### 짧은 조사

```markdown
## 답

질문에 대한 직접적인 답변

## 근거

- 핵심 근거와 필요한 조건

## 출처

- 답변을 직접 뒷받침하는 자료
```

### 개요·비교·근거 종합

```markdown
## 결론

사용자가 가장 먼저 알아야 할 내용

## 핵심 발견

- 발견 1
- 발견 2

## 차이 또는 쟁점

필요한 경우 비교, 불일치, 해석을 설명

## 한계

확인하지 못했거나 일반화하기 어려운 부분만 기재

## 출처

핵심 주장을 뒷받침하는 자료
```

형식을 그대로 강제할 필요는 없다. 짧은 질문에는 짧게 답하고, 복잡한 질문에만
구조를 늘린다.

## 10. 흔한 실패

- 검색 결과의 요약문만 보고 사실을 확정한다.
- 질문에 답하지 않고 조사한 자료만 나열한다.
- 오래된 정보를 현재 사실처럼 쓴다.
- 서로 같은 원출처를 인용한 문서들을 독립 근거로 본다.
- 인용한 출처가 실제 주장과 다른 내용을 말한다.
- 사실, 해석, 추천을 구분하지 않는다.
- 모든 질문에 긴 보고서를 작성한다.
- 자료가 없는데도 자연스러운 문장으로 빈칸을 채운다.

## 11. 최종 체크리스트

- 사용자의 질문에 직접 답했는가?
- 검색 요약이 아니라 원문을 확인했는가?
- 중요한 사실과 날짜가 맞는가?
- 결론을 바꿀 사실은 교차 확인했는가?
- 사실과 해석을 구분했는가?
- 출처가 해당 주장을 직접 뒷받침하는가?
- 불확실한 내용을 단정하지 않았는가?
- 필요한 만큼만 간결하게 썼는가?

## 12. 핵심 인사이트

좋은 Research Skill은 복잡한 조사 시스템이 아니다. 질문에 맞는 자료를 찾아
원문을 확인하고, 중요한 사실을 검증한 뒤, 사용자가 바로 이해할 수 있는 답과
출처를 제공하는 기본 동작을 안정적으로 수행하는 Skill이다.

Research Skill을 분류할 때는 목적, 대상·정보원, 방법을 섞지 않아야 한다.
사실 확인, 개요, 비교, 최신 동향, 근거 종합은 하나의 Skill 안에서 바뀔 수
있는 목적 모드다. 반면 웹, 논문, 문서, 코드, 데이터는 필요한 도구와 확인
방식이 크게 달라 별도 Research Skill을 나누는 실용적인 경계가 될 수 있다.

방법은 그 Skill이 대상을 다루는 구체적인 능력이다. 예를 들어 Web Research는
웹 검색과 브라우징, Codebase Research는 파일·심볼 검색과 참조 추적, Data
Research는 질의와 계산이 중심이 된다. 최종적으로는 선택한 목적, 대상, 방법을
조합해 같은 기본 흐름으로 답과 출처를 제공한다.
